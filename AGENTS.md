# Repository instructions

## Publishing responsibilities

The repository owner's standing instruction is that **the user manually uploads or edits
the CurseForge project-page description**.

- Maintain `curseforge.md` as the ready-to-use page copy. The publisher also prepares
  `build/publishing/runs/<run>/curseforge-description.md` for the user's author dashboard.
- Do not open the CurseForge author dashboard or attempt API/browser automation to update
  its project page unless the user explicitly requests that action in a later instruction.
- Do not ask the user to reconfirm this division of work on each release. The manual page
  update is expected; it is not a publishing failure, blocker or unfinished agent task.
- When the page copy changes, provide its path as the handoff without repeatedly prompting
  the user to upload it or reporting that the page was not synchronized.
- This rule concerns the project page. Authorized CurseForge JAR uploads and Modrinth
  description synchronization continue through the existing publishing script.

See `PUBLISHING.md` for the complete build and release workflow.
